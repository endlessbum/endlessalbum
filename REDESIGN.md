Полный кардинальный редизайн Endlessalbum

Этот промт объединяет два исходных запроса:

1. «Style prompt / Design system for Grok.com-inspired interface» — тихая, инструментальная эстетика с чёрно-белыми поверхностями, hairline-границами и экономным акцентом.
2. «Современный веб-интерфейс в эстетике Grok» — тёмная премиальная тема, левый sidebar, центральная область, архитектура компонентов, состояния, адаптивность.

Оба источника адаптированы под реальную структуру проекта Endlessalbum (приложение для пар: общий альбом воспоминаний, чат, мини-игры, музыка, счётчики, настройки). Это не AI-чат — промт про дизайн-систему и структуру интерфейса, а не про копирование функционала Grok (разве что копирование интерфейса).

---

0. Роль и контекст

Ты — senior frontend-архитектор и дизайнер.  
Перед тобой существующее React-приложение Endlessalbum («Альбом»): русскоязычный сервис воспоминаний для пар. Общий аккаунт двоих хранит воспоминания (фото / видео / текст / цитата), чат, музыку, мини-игры и настройки.

Твоя задача — полный кардинальный редизайн интерфейса.  
Это не «перекрасить в тёмное», а переосмыслить архитектуру экранов, навигацию, компоненты, типографику, состояния и микроинтеракции.  

Существующий функционал, API и данные трогать нельзя — меняется только представление (клиентский код, компоненты, стили).

Стек:  
React 18 + TypeScript + Vite, Wouter (роутинг), TanStack Query, Tailwind, shadcn/ui (Radix), lucide-react, WebSocket (`shared/ws-messages.ts`), `client/src/index.css` + `tailwind.config.ts` как единая дизайн-система.

1. Главное требование: кардинальное изменение

Прошлый редизайн изменил только цвета — это недопустимо. Редизайн должен быть структурным и визуально очевидным:

1. Нижний бар навигации убирается. Все вкладки и управление переносятся в левую вертикальную колонку (Sidebar), которая присутствует на всех экранах авторизованного пользователя.
2. Сетка-витрина карточек на главной остаётся по смыслу (переворачивающиеся карточки-воспоминания — фирменная фишка проекта), но полностью перерабатывается визуально под новую дизайн-систему.
3. Каждая страница получает новую архитектуру, иерархию и ритм.
4. Пользователь при первом взгляде должен почувствовать:  
   «Это премиальный современный продукт уровня Grok / ChatGPT / Claude»,  
   но при этом интерфейс остаётся узнаваемым именно как альбом пары.

2. Визуальная философия

Quiet · Focused · Engineered restraint · Research-lab minimalism
(тихий, сфокусированный, инженерная сдержанность, минимализм исследовательской лаборатории)

- Минимализм, спокойствие, ощущение «инструмента», а не «панели управления».
- Большие намеренные пустые пространства вокруг главного действия.
- Глубина строится только за счёт контраста трёх разрешённых цветов, тонких границ и аккуратных скруглений.
- В приложении используется строго три цвета, без исключений:
  - `#000000` — основной цвет: фон приложения, фон Sidebar, основные поверхности и контейнеры.
  - `#FFFFFF` — основной светлый цвет: основной текст, заголовки, иконки, кнопки и их содержимое. Текст внутри белых кнопок — чёрный.
  - `#B6B6B6` — второстепенный цвет: вторичный и мета-текст, подписи, неактивные элементы, границы, разделители и вспомогательные элементы.
- Никаких других цветов, оттенков, цветовых градиентов или цветных акцентов.
- Не использовать `hsl`, `hsla`, `rgb`, `rgba`, другие hex-цвета или CSS-цветовые значения вне трёх разрешённых цветов.
- Не использовать прозрачность, если она создаёт новый визуальный оттенок. Для слабых разделителей и состояний использовать только `#B6B6B6`.
- Hover, focus, active, disabled и selected состояния не должны вводить новые цвета.
- Никаких градиентов, glow-эффектов, цветных свечений, визуального шума, игровых анимаций.

Цветовая система (design tokens в `:root`)

Единая палитра приложения:
- `--background: #000000`
- `--surface: #000000`
- `--surface-hover: #B6B6B6`
- `--surface-soft: #B6B6B6`
- `--foreground: #FFFFFF`
- `--text-primary: #FFFFFF`
- `--text-secondary: #B6B6B6`
- `--text-muted: #B6B6B6`
- `--border: #B6B6B6`
- `--border-subtle: #B6B6B6`
- `--accent: #FFFFFF`
- `--ring: #B6B6B6`
- `--danger: #B6B6B6`
- `--success: #B6B6B6`

Важно: эти токены не должны получать значения других цветов. Для success, danger, warning, info, selection, links и иных состояний не добавлять отдельные цвета.

Тёмная тема — единственная визуальная тема приложения. `ThemeProvider` должен использовать только эту палитру. Отдельную цветовую схему с другими значениями не создавать.

Токены должны быть централизованы:
`--background`, `--foreground`, `--surface`, `--surface-hover`, `--surface-soft`, `--border`, `--border-subtle`, `--text-primary`, `--text-secondary`, `--text-muted`, `--accent`, `--danger`, `--success`, `--ring`, `--radius`, `--font-sans`, шкала теней.
Всё синхронизируется с `tailwind.config.ts`.

Типографика

- Современная геометрическая / системная sans-serif (Inter / system-ui / SF Pro).
  Для проекта допустимо сохранить текущий моноширинный акцент (Pitagon Sans Mono) как фирменный технический стиль для лейблов / меток / eyebrow, но основной текст должен читаться легко.
- Крупные воздушные заголовки с лёгким отрицательным трекингом на больших размерах.
- Body ≈ 16px, line-height 1.5–1.6.
- Вторичный / мета-текст — мельче и выполняется в `#B6B6B6`.
- Иерархия через размер + вес + три цвета палитры, а не сплошной bold.
- Не слишком крупные заголовки. Компактность.

Форма (shape language)

- Скруглённые прямоугольники 8–16–24px для карточек / панелей.
- Полностью скруглённые (pill, 9999px) для основного поля ввода и поиска.
- Круглые кнопки действия (отправка).
- Крайне сдержанные тени — предпочтение границе `#B6B6B6` + контрасту `#000000` / `#FFFFFF`.

3. Новая архитектура интерфейса (AppShell + Sidebar)

Все авторизованные страницы (Главная, Чат, Музыка, Игры, Профиль, Настройки) оборачиваются в `AppShell`:

```
┌──────────────────────────────────────────────────────────┐
│  [Sidebar]   │           Content (роут)                  │
│  ──────────  │                                           │
│    logo      │                                           │
│  ──────────  │                                           │
│  • Главная   │                                           │
│  • Музыка    │                                           │
│  • Игры      │                                           │
│  • Чат       │                                           │
│  ──────────  │                                           │
│  • Профиль   │                                           │
│  • Настройки │                                           │
└──────────────────────────────────────────────────────────┘
```

3.1. Sidebar (левый, вертикальный) — новый компонент

- Фон `#000000`, визуально отделённый от контента тонкой границей `#B6B6B6`.
- Верх:
  - Логотип / название приложения (Endlessalbum), компактно.
  - Кнопка «Создать воспоминание» (или «+» с выпадающим меню «Текст / Фото / Видео / Цитата»).
- Середина — навигация по вкладкам:
  - Главная (`/`)
  - Музыка (`/music`)
  - Игры (`/games`)
  - Сообщения (`/messages`)
  - Профиль (`/profile`)
  - Настройки (`/settings`)
  - Каждый пункт — иконка + подпись. Активный пункт выделяется только сочетанием `#000000`, `#FFFFFF` и `#B6B6B6` без новых цветов. При наведении — плавное изменение фона.
- Низ:
  - Мини-плеер (текущий трек: обложка, название, автобегущая строка).
  - Профиль пользователя (аватар + имя) и настройки.
  - Дополнительные пункты меню (logout).

Важно:
Поиск полностью убирается из Sidebar.
Поиск появляется только на страницах, где он нужен (Главная, Музыка и при необходимости другие), и располагается вверху экрана по центру в зоне контента / TopBar.

Состояния Sidebar:
- Expanded на desktop (полная ширина ≈ 240–280px).
- Collapsed на desktop.
- Mobile: sidebar скрыт, открывается выезжающей панелью (drawer) по кнопке-бургеру в шапке. Поверх контента, с затемнением.

Гарантии доступности: 
Навигация остаётся доступной для `getByRole('link')` с теми же именами (Главная, Музыка, Сообщения, Профиль, Настройки).  
`getByRole('button')` для «Добавить». На странице должен быть ровно один элемент с именем «Добавить» в навигации. Если на странице контента есть своя кнопка «Добавить» — ей нужно другое accessible-имя.

3.2. AppShell / Content

- Центральная область — главный фокус. Контент на больших экранах не должен растягиваться на всю ширину: ограниченная колонка (`max-width ≈ 56–72rem`) для читаемости.
- Никакого нижнего плавающего бара.
- Глобальный контейнер: `h-[100dvh]` / `min-h-screen`, без горизонтального скролла.

3.3. TopBar / зона поиска

- Верхняя панель текущей страницы: заголовок, компактные действия справа, меню.
- Элементы максимально спокойные, не конкурируют с контентом.
- На mobile — кнопка-бургер для drawer.
- Поиск (где он нужен) размещается по центру верхней части контентной области / TopBar.  
  Форма — пилюльная, спокойная, на токенах поверхностей, без визуального шума.  
  Поиск присутствует на:
  - Главной (поиск по хэштегам / словам)
  - Музыке (поиск по трекам)
  - И при необходимости на других страницах, где поиск уместен.

5. Состояния и микроинтеракции

Состояния, которые нужно реализовать корректно:
- empty, loading (skeleton предпочтительнее), typing, streaming/generating, error / retry, file/image attached, sidebar collapsed / mobile opened, message copied, активный пункт навигации, disabled / recording.

Микроинтеракции:
- Плавные, короткие, функциональные. Никаких агрессивных bounce и «геймерских» эффектов.
- Hover: лёгкое изменение только между `#000000`, `#FFFFFF` и `#B6B6B6` без новых цветов.
- Focus: аккуратные focus-ring на основе `--ring`.
- Transitions: `background-color` / `opacity` 150–200ms, `transform` только там, где полезно.

6. Адаптивность

- **Desktop (≥1024):** полноценный левый Sidebar (expanded / collapsed), ограниченная колонка контента.
- **Tablet (768–1023):** уменьшенный / collapsed sidebar.
- **Mobile (<768):** sidebar скрыт, открывается drawer по бургеру.
- **Ultrawide:** контент остаётся в разумной ограниченной ширине.
- Критично: **никакого горизонтального скролла** (в т.ч. на 390×844).  
  Проверка: `document.documentElement.scrollWidth <= clientWidth`.
- Учитывать `env(safe-area-inset-bottom)`. После удаления нижнего бара проверить, что нигде не осталось пустого отступа `pb-bottom-nav`.

7. Критические контракты — НЕ ЛОМАТЬ

Редизайн обязан сохранить обратную совместимость. Следующие вещи обязаны остаться нетронутыми (их проверяют Playwright E2E):

7.1. Accessible names
- `getByRole('link', { name: 'Главная' })`, `'Музыка'`, `'Сообщения'`, `'Профиль'`, `'Настройки'`
- `getByRole('button', { name: 'Добавить' })` — ровно один в навигации
- Заголовки страниц и модалок

7.2. data-testid
Сохранить все существующие `data-testid` (home-page, chat-page, memory-card-*, message-*, game-card-*, tab-*, input-*, button-*, search-input-desktop, search-input-mobile и т.д.).

7.3. localStorage и CSS-контракты
- `app-theme` = `dark`
- `ui:font`, `ui:chatBackground`
- Класс `light` на `<html>` не используется для смены палитры
- Reset настроек возвращает `--font-sans` к дефолту

7.4. E2E
После редизайна прогнать `npm run -s e2e` (или целевые спеки) и убедиться, что не появилось новых падений.
